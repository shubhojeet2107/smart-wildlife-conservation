# Planned Database Tables

These are the agreed initial table names. Add columns and relationships in each service's own code and migration scripts.

- `wildlife_db`: `species`, `animals`, `animal_sightings`
- `protected_area_db`: `protected_areas`, `zones`, `habitats`, `water_resources`
- `patrol_db`: `patrols`, `patrol_assignments`, `patrol_observations`
- `incident_db`: `incidents`, `incident_updates`
- `rescue_db`: `rescue_cases`, `treatment_records`
- `resource_db`: `users`, `roles`, `staff`, `resources`, `resource_allocations`
- `conservation_db`: `conservation_programmes`, `programme_activities`

## Database rules
- Use PostgreSQL `BIGINT GENERATED BY DEFAULT AS IDENTITY` or JPA-generated IDs.
- Add `created_at` and `updated_at` timestamps to important records.
- Add indexes for commonly filtered columns such as `zone_id`, `status`, and `reported_at`.
- Use foreign keys only between tables owned by the same service.
- For production-style schema management, use Flyway migrations rather than relying on `ddl-auto=update`.
